# Task for researcher

Research question: does a client that POSTs to an OpenAI-compatible /v1/chat/completions endpoint work correctly when routed through a LiteLLM proxy (BerriAI/litellm, current version)?

The client sends this exact JSON body to {base_url}/chat/completions:
{"model": "...", "messages": [...], "temperature": 0.0, "max_tokens": 1, "logprobs": true, "top_logprobs": 20, "chat_template_kwargs": {"enable_thinking": false, "preserve_thinking": false}}
and then reads choices[0].logprobs.content[0].top_logprobs = [{token, logprob}, ...]. It needs the top-K logprob list to survive the proxy round trip.

Answer these specific questions with primary sources (LiteLLM docs at docs.litellm.ai, and BerriAI/litellm GitHub issues/code — cite URLs and note version/date):
1. Does the LiteLLM proxy return `logprobs` / `top_logprobs` for chat completions? Is it supported for all providers or only some? Look for the `supports_logprobs` / `supports_top_logprobs` capability flags in LiteLLM's supported-params machinery and which providers set them.
2. When a provider does not support logprobs, does LiteLLM (a) reject the request with 400, (b) silently drop it, or (c) error only when `drop_params=False`? What is the default behavior of `drop_params` for unknown/unsupported params?
3. Does LiteLLM forward unknown/non-standard top-level body params such as `chat_template_kwargs` (vLLM/SGLang extension) to an upstream OpenAI-compatible server (e.g. model name `openai/Qwen3-8B` with a vLLM api_base)? Or are they dropped/rejected? Is there a documented way to pass them through (extra_body, additional_drop_params, openai_extra_params, wildcards, `litellm_extra_body`, passthrough settings)?
4. Does a `max_tokens: 1` + `logprobs: true` request survive unchanged (no forced streaming, no rewriting of max_tokens, no router-level retries that would double the cost)?
5. Known issues: search GitHub issues for "logprobs" + litellm proxy (especially "logprobs not returned"/"top_logprobs dropped"), note whether they are open/closed and in which release they were fixed.
6. Anything about LiteLLM stripping `logprobs` when the response is transformed (e.g. anthropic/bedrock/google providers) or when using guardrails/hooks.

Return a short brief: a VERDICT line (works / works-with-config / broken), the exact config keys needed if it works-with-config (a minimal litellm config.yaml example), and the caveats. Prefer current-version facts and say so.
